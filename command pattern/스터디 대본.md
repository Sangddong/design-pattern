## 1. 커맨드 패턴이란

커맨드 패턴은 **행위 패턴**에 속합니다.

핵심은 이겁니다.

- 보통은 리모컨이 조명에 직접 `on()`을 호출합니다.
- 커맨드 패턴에서는 “조명 켜기”라는 **요청 자체를 객체**로 만듭니다.
- 리모컨은 그 객체의 `execute()`만 호출합니다.

그래서 역할이 이렇게 나뉩니다.

| 역할 | 의미 | 예시 |
| --- | --- | --- |
| Command | 실행할 작업의 공통 인터페이스 | `Command` |
| ConcreteCommand | 실제 요청을 담은 객체 | `LightOnCommand` |
| Invoker | 명령을 실행시키는 쪽 | `RemoteControl` |
| Receiver | 실제로 일하는 쪽 | `Light`, `MusicPlayer` |
| Client | 명령을 만들고 리모컨에 연결 | `Main` |

여기서 중요한 포인트는,

**리모컨은 Light나 MusicPlayer의 구체 메서드를 몰라도 된다**는 점입니다.  
그냥 `execute()`, `undo()`만 알면 됩니다.

## 2. 상황 (01_초기 상황.png)

처음 상황을 보겠습니다.

카페에 리모컨이 있고, 조명과 음악 플레이어를 제어하려고 합니다.

- 조명: `on()`, `off()`
- 음악: `play()`, `stop()`

초기 코드에서는 리모컨이 기기를 직접 들고 있습니다.

```java
public class RemoteControl {
    private Light light;
    private MusicPlayer musicPlayer;

    public void onButton() {
        light.on();
    }

    public void offButton() {
        light.off();
    }
}
```

당장은 동작합니다.  
버튼 누르면 조명이 켜지고 꺼집니다.

---

## 3. 문제 상황

여기서 기획이 바뀝니다.

> 조명만 조절하면 끝이 아니라,  
> **음악 재생/정지까지 같은 리모컨으로 제어**해야 하고,  
> 나중에는 **undo(되돌리기)** 도 필요합니다.

즉, 해결해야 할 이슈는 이겁니다.

- 버튼에 여러 기기 동작을 연결해야 함
- 기기마다 메서드 이름이 다름 (`on` vs `play`)
- 나중에 동작 추가, 변경, 취소가 가능해야 함

## 4. 잘못된 해결책 (02_잘못된 해결책.png)

가장 먼저 떠오르는 방법은 if-else입니다.

```java
public void buttonPressed(int button) {
    if (button == 0) {
        light.on();
    } else if (button == 1) {
        light.off();
    } else if (button == 2) {
        musicPlayer.play();
    } else if (button == 3) {
        musicPlayer.stop();
    }
}
```

문제는 명확합니다.

1. 기기가 늘 때마다 리모컨 코드를 고쳐야 합니다.
2. 리모컨이 모든 기기의 API를 알아야 합니다.
3. undo나 매크로처럼 “요청을 저장했다가 다시 실행”하기가 어렵습니다.

즉, **요청을 보내는 쪽과 수행하는 쪽이 너무 강하게 결합**된 상태입니다.

## 5. 커맨드 패턴 해결책 (03_최종 해결책.png)

그래서 요청을 객체로 분리합니다.

### 5-1. Command 인터페이스

```java
public interface Command {
    void execute();
    void undo();
}
```

모든 동작은 이제 `execute()`로 실행하고, `undo()`로 되돌립니다.

### 5-2. 구체 명령 객체

예를 들어 조명 켜기는 이렇게 됩니다.

```java
public class LightOnCommand implements Command {
    private Light light;

    public LightOnCommand(Light light) {
        this.light = light;
    }

    public void execute() {
        light.on();
    }

    public void undo() {
        light.off();
    }
}
```

포인트는,

- 실제로 일을 하는 건 여전히 `Light`
- 하지만 리모컨은 `Light`를 직접 호출하지 않음
- `LightOnCommand`가 중간에서 “조명 켜기 요청”을 대신 들고 있음

음악도 마찬가지입니다.  
`MusicPlayCommand`가 `musicPlayer.play()`를 호출하면 됩니다.

### 5-3. 리모컨은 Command만 보관

```java
public class RemoteControl {
    private Command[] onCommands;
    private Command[] offCommands;
    private Command undoCommand;

    public void setCommand(int slot, Command onCommand, Command offCommand) {
        onCommands[slot] = onCommand;
        offCommands[slot] = offCommand;
    }

    public void onButtonWasPushed(int slot) {
        onCommands[slot].execute();
        undoCommand = onCommands[slot];
    }

    public void undoButtonWasPushed() {
        undoCommand.undo();
    }
}
```

이제 리모컨 입장에서는

- 0번 슬롯이 조명인지 음악인지 몰라도 됩니다.
- 그냥 그 슬롯의 `execute()`만 호출하면 됩니다.

빈 슬롯은 `NoCommand`를 넣어서 null 체크를 줄입니다.

### 5-4. 사용 예시

```java
RemoteControl remote = new RemoteControl();
Light hallLight = new Light("홀");
MusicPlayer musicPlayer = new MusicPlayer();

remote.setCommand(0, new LightOnCommand(hallLight), new LightOffCommand(hallLight));
remote.setCommand(1, new MusicPlayCommand(musicPlayer), new MusicStopCommand(musicPlayer));

remote.onButtonWasPushed(0);   // 홀 조명 ON
remote.offButtonWasPushed(0);  // 홀 조명 OFF
remote.undoButtonWasPushed();  // 다시 ON

remote.onButtonWasPushed(1);   // 음악 재생
remote.undoButtonWasPushed();  // 음악 정지
```

여기서 볼 수 있는 이득은 세 가지입니다.

1. **확장 쉬움**  
   새 기기 추가는 Command 클래스 추가 + `setCommand`면 됩니다.
2. **결합도 낮음**  
   리모컨은 구체 기기 API를 모릅니다.
3. **undo 가능**  
   마지막 실행 Command를 저장해두면 되돌리기 구현이 쉽습니다.

## 6. 언제 쓰면 좋은지

커맨드 패턴은 이런 때 쓰기 좋습니다.

- 버튼, 메뉴, 단축키처럼 “동작”을 연결해야 할 때
- 실행 취소(undo), 재실행(redo)이 필요할 때
- 요청을 큐에 넣거나, 나중에 실행하거나, 로그로 남기고 싶을 때

반대로, 그냥 메서드 한 번 호출하면 끝나는 단순한 경우에는  
굳이 커맨드 객체까지 만들 필요는 없습니다.

## 7. 한 줄 정리

마지막으로 다시 한 줄로 정리하겠습니다.

> **커맨드 패턴은 “무엇을 실행할지”를 객체로 포장해서,  
> 실행을 요청하는 쪽과 실제로 수행하는 쪽을 분리하는 패턴입니다.**

다이어그램 기준으로 보면,

- 01: 리모컨이 기기를 직접 호출
- 02: if-else로 억지 연결
- 03: Command로 요청을 객체화해서 슬롯에 장착

이 흐름으로 이해하시면 됩니다.

질문 있으시면 받겠습니다.
